# WebiList — регистрация участников вебинаров

Готовый консольный проект на основе исходного main.py. Регистрации и отметки
посещения хранятся в SQLite и сохраняются между запусками. Python 3.9 или новее;
внешние библиотеки и установка отдельного сервера БД не нужны.

## Запуск

Распакуйте архив, откройте терминал в папке WebiList и выполните:

```sh
python3 main.py
```

На Windows можно использовать `py main.py`.
При первом запуске автоматически создаётся data/webinars.db и добавляются три
вебинара из исходного проекта. При повторном запуске данные не сбрасываются.
Путь к базе определяется относительно файлов проекта, а не текущей папки терминала.
Можно указать отдельную базу: `python3 main.py --db demo.db`.

## Возможности

1. Просмотр расписания, спикеров, категорий, дат и времени.
2. Регистрация по имени и email с проверкой ввода и защитой от дубликатов.
3. Просмотр зарегистрированных участников.
4. Установка и снятие отметки посещения.
5. Статистика регистраций и посещений по каждому вебинару.

Имя участника едино для всех регистраций. Если email уже существует с другим
именем, программа просит указать прежнее имя. Email приводится к нижнему регистру;
поддерживаются обычные ASCII-адреса. Доступность почтового ящика не проверяется.

Это локальная учебная версия без входа по паролю: любой пользователь, запустивший
программу, имеет функции организатора. Исходные даты сохранены. Для демонстрации
можно регистрироваться и на прошедшие вебинары, как в исходной программе.
Отсечение прошедших событий и разграничение ролей из плана ПР2 относятся к будущей
веб-версии. Веб-сайт и Django в этот консольный проект не входят.

## Структура

- main.py — консольное меню и обработка ввода.
- database.py — работа с SQLite, бизнес-правила и начальное расписание.
- schema.sql — пять таблиц, внешние ключи, ограничения и индексы.
- tests/test_project.py — автоматические проверки, включая перезапуск и меню.
- data/webinars.db — создаваемая при запуске база; в архив не включена.

База включает participants, speakers, categories, webinars и registrations.
Связь участников и вебинаров — многие ко многим через registrations.
Пара participant_id + webinar_id уникальна; attended имеет значения 0 и 1.
Время хранится в UTC и показывается по Москве (UTC+3). Регистрация выполняется
в транзакции, запросы используют параметры, внешние ключи включены для подключения.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

Тесты создают временные базы и не затрагивают рабочие регистрации.

## Демонстрация

Выберите 2, затем вебинар 1; введите имя и email. Откройте пункт 3.
В пункте 4 выберите участника и введите 1. Завершите программу через 0,
запустите снова и проверьте пункт 3: запись и посещение сохранятся.
Повторная регистрация того же email на тот же вебинар будет отклонена.

Для резервной копии закройте программу и скопируйте data/webinars.db.
Чтобы начать демонстрацию с чистого состояния, укажите новый путь через --db.
Не удаляйте существующую базу, если её данные нужны.

ПР3 описывает предыдущий этап до подключения БД; текущая реализация идёт дальше него.
